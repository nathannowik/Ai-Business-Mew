# Deploying Mew AI

Two ways to try it: run it **locally** (fastest), or **deploy** it for a
shareable URL. Everything works with zero external keys (in simulation mode) —
add provider keys later to make AI/phone/payments real.

---

## Option A — Run locally (~5 minutes)

Requires Node 20+ and Docker (for Postgres).

```bash
git clone <your-repo-url>
cd Ai-Business-Mew
git checkout claude/ai-business-automation-platform-4orsg0

npm install
cp .env.example .env          # optional: add ANTHROPIC_API_KEY for real AI replies
npm run db:up                 # starts Postgres in Docker
npm run db:migrate            # creates tables
npm run db:seed               # demo login: demo@mew.ai / demo1234

npm run dev:api               # terminal 1  → http://localhost:4000
npm run dev:web               # terminal 2  → http://localhost:3000
```

Open http://localhost:3000 and sign in with **demo@mew.ai / demo1234**.

## Option B — Deploy for a public link (~15 minutes, free tiers)

This repo includes a **Render Blueprint** (`render.yaml`) that provisions a
Postgres database, the API (Docker), and the web app together.

1. Push this branch to your own GitHub repo (it already is).
2. Go to <https://render.com> → **New → Blueprint** → connect the repo.
   Render reads `render.yaml` and creates **mew-db**, **mew-api**, **mew-web**.
3. First deploy finishes with placeholder URLs. Now set the cross-links
   (Render → each service → Environment):
   - **mew-api**: `PUBLIC_API_URL` = the mew-api URL (e.g. `https://mew-api.onrender.com`),
     `APP_BASE_URL` = the mew-web URL.
   - **mew-web**: `NEXT_PUBLIC_API_URL` = the mew-api URL, then **Manual Deploy →
     Clear build cache & deploy** (Next bakes this at build time).
4. Open the **mew-web** URL. The database starts empty — click **Sign up** to
   create your first workspace (there's no seeded demo in a fresh deploy).

`JWT_SECRET` and `INTEGRATION_ENCRYPTION_KEY` are auto-generated by Render.

> Prefer other hosts? The API is a standard Dockerfile (`apps/api/Dockerfile`,
> build context = repo root) — it runs anywhere that takes a container
> (Railway, Fly.io, etc.). The web app is a normal Next.js app; Vercel works if
> you set the root to `apps/web` and build from the repo root so the
> `@mew/shared` workspace resolves.

## Turning on real providers (optional)

Everything below is optional — the product runs in simulation mode without it.

| Capability | Env var(s) | Where |
|-----------|-----------|-------|
| AI replies (all services) | `ANTHROPIC_API_KEY` | mew-api |
| Call transcription | `OPENAI_API_KEY` | mew-api |
| Phone + SMS | `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER` | mew-api |
| Billing | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | mew-api |

**Twilio:** point your number's Voice webhook at
`POST {PUBLIC_API_URL}/webhooks/twilio/voice/incoming` and Messaging at
`POST {PUBLIC_API_URL}/webhooks/twilio/sms?orgId=<org id>`.

**Stripe:** add a webhook to `POST {PUBLIC_API_URL}/webhooks/stripe` and copy the
signing secret into `STRIPE_WEBHOOK_SECRET`.

> Note on free tiers: Render's free web services sleep when idle, so the first
> request after a pause takes a few seconds to wake. Fine for testing.
